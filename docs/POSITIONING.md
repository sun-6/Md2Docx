# 产品定位一页纸

## 一句话

**离线、中文友好、AI 优先的 Markdown ⇄ Word 双向转换器。**

## 三类用户，三条路径

| 用户 | 入口 | 核心诉求 | 我们给的东西 |
|---|---|---|---|
| 普通办公者 | GUI（拖拽） | md 变排版好的 Word，别让我装环境 | 双击即用、方向自动识别、自动体检 |
| 技术写作者 | CLI | 脚本化、可校验、结果可编程 | JSON 契约、lint/verify、批量与管道 |
| AI Agent | 技能包 | 一句话完成文档转换 | 任务路由式 SKILL + PATH 一键启用 |

## 差异化（为什么用这个而不是……）

| 对比对象 | 它们的方式 | 我们的差异 |
|---|---|---|
| pandoc 裸用 | 需自装环境；表格内 HTML/公式在 Word 中丢失 | 内置全链路离线；Lua 过滤器让这些内容在 Word 存活 |
| Markdown Preview Enhanced | 预览优秀，但 docx 导出丢 HTML 表格 | 同等预览语法 + 原生表格转换（colspan 保留） |
| 在线转换服务 | 需联网、有隐私顾虑 | 完全离线，文档不出本机 |
| AI 直接生成 docx（docx-js 等） | 代码生成式，逐条映射公式 | 声明式转换，同一 md 双输出（docx+html） |

## 三个不可妥协

1. **离线优先**：内置 pandoc/浏览器/mermaid 的 250MB 是特性不是负担
2. **静默丢失零容忍**：lint（输入侧）+ warnings（过程）+ verify（输出侧）三层防线
3. **同一事实源**：GUI 与 CLI 消费同一核心，行为永远一致

## 许可与社区

GPL-3.0-or-later（由 Fluent-Widgets 依赖决定）。接受 issue 模板引导的反馈，
`check --json` 是标准诊断信息。CI 双平台跑回归。
