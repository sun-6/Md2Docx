# Md2Docx 转换技能

## 1. 定位 CLI

按顺序尝试，任一成功即用：

1. `md2docx-cli --version` —— 已通过 GUI "AI 支持" 注册到 PATH（写入的是单目录版安装目录）
2. 环境变量 `MD2DOCX_PATH` 指向的 exe（用户手动设置的可选项）
3. 单目录版安装目录下的 `md2docx-cli.exe`（与 `Md2Docx_Pro.exe` 同目录）

全部失败时先分辨版本：单文件版 `Md2Docx_Pro_OneFile.exe` 只含 GUI，**不携带 CLI**（其同目录永远不会有 md2docx-cli.exe）——请用户改从 GitHub Releases 下载单目录版 `Md2Docx_Release_File_*.zip`；若是单目录版，请用户打开 GUI 中的 "AI 支持" 按钮完成启用，或直接告知安装目录。

**所有命令始终带 `--json`**（stdout 单个 JSON、日志在 stderr、退出码 0/1/2）。

## 2. 任务路由

| 用户意图 | 执行步骤 |
|---|---|
| 从零撰写文档/报告 | 按 §5 生成规范产出 md（含 front matter 与参考文献框架）→ `lint` 修全部 error → `convert --verify --json` → 检查 `warnings` 后交付 |
| 把 md 转成 Word/HTML | `lint` → 有 error 先修 → `convert --verify --json` → 检查 `warnings` 与 `verify`，必要时修复重转 |
| 修改用户的 Word 文档 | `extract 报告.docx -o work/报告.md --json` → 编辑 md → `convert work/报告.md --json` |
| 文档能不能转/有什么问题 | `lint 文档.md --json`（不产出文件；`--deep` 可校验 mermaid 语法） |
| 渲染一张图表为图片 | `render-mermaid 图.mmd -o 图.png --json`（`--theme dark` 可选） |
| 转换整个目录 | `convert <目录> -o <输出目录> --json`（聚合结果，含每个文件的成败） |
| 首次使用/环境异常 | `check --json` 先自检六项组件 |

## 3. 结果契约（所有命令一致）

- 退出码：`0` 成功（lint 允许 warning/info） / `1` 失败或存在 error / `2` 用法错误
- 失败时读 `error.{code, message, remediation}` 并**按 remediation 行动**，不要盲目重试
- `warnings[]`：转换成功但部分内容降级（如某张图渲染失败）——必须阅读并决定是否修复
- `output`：输出文件绝对路径；`cache.{hit, rendered}`：图表缓存命中/渲染数

## 4. 失败模式与高频坑

- **⚠️ 转换成功 ≠ 万事大吉**：`warnings` 非空表示有内容降级（最常见：mermaid 语法错误、远程图片下载失败）。修复源 md 后重转，缓存会自动命中未变更部分；关键文档建议加 `--verify` 校验输出结构一致性
- **不要"顺手清理" `.md2docx_images`**：删除后含图文档会重新渲染全部图表（5–30s），保留则二次转换 <2s
- **远程图片需要网络**：离线环境先把 `![](https://...)` 本地化（lint 会提示具体行号）
- 公式编号 `\tag{X}` 会被自动改写为可见的 `(X)`，无需手工处理
- extract 得到的 md 中媒体在 `media/` 目录——编辑时保持相对路径，转回时会自动缓存
- Word 文档被占用（正在 Word 中打开）时 extract 会失败，先让用户关闭

## 5. 表达能力与生成规范（产出 md 时）

**写作硬性要求（以下规则约束产出的文档正文，不约束与用户的对话、代码与提交说明）**

这些规则的共同目的：让非技术读者顺畅读懂全文，并让每个论断与数字可被核验。

**一、语言范式（书面白话与去 AI 味）**

- **书面白话**：严禁使用工程/统计黑话（如门禁、管线、落盘、口径、臂、契约、病灶等）及抽象隐喻。使用通用、规范的书面日常中文（如：检查项、处理流程、保存记录、统计定义、对照组等）。保持正式语气，禁止口语化聊天体。禁词表针对的是隐喻/行话用法；词汇在其专业场景的规范术语义不受限（如数学矩阵、统计口径）
- **去模板化**：禁止"首先/其次/最后"、"总而言之"等机械连接词。段落间须通过语义和上下文逻辑自然过渡，将方法论有机融合，严禁无脑罗列步骤。操作/安装等真实步骤仍应使用有序列表，被禁的是段落间的机械过渡
- **去空洞词**：禁用"赋能、闭环、抓手、下沉、底座"等无实义词汇，只使用具有具体物理或业务含义的词汇
- **费曼准则**：假设读者为非技术背景但逻辑严密的业务负责人，表述直白自然、因果清晰。直白表述与严格推导并行不悖：推导层保持严密，语言层保持直白

**二、严谨性与推导规范（公式/图表/数据）**

- **一符一义与量纲一致**：全文同一语义仅使用单一符号，变量必须标注量纲与单位，推导过程前后逻辑与物理量纲严格匹配
- **三者同源**：公式、图表与正文论证严格绑定，图表即论证结构本身而非装饰。落地方式：数据图表用 `chart` 围栏内嵌 JSON 原始数据（天然可复现），正文数据表给出原始数据与来源，不得为示意目的编造数值
- **实证与因果边界**：凡涉及"X 带来了提升"的因果表述，必须有消融实验、受控对照或推导证明支撑；缺乏实证数据时，只能进行相关性描述或逻辑推演。严禁编造数据、文献或出处：正文提及的任何指南、标准、规范、文献（含作为方法论或风格依据的）必须真实可核实，不得虚构书名、文件名来支撑结论或写作风格

**三、章节结构（上下文契约，去套话导言）**

含两个及以上章节的文档，每章开头第一段必须显式交代输入条件（基于上一章产出的什么结论/数据）与输出承诺（本章为后续提供什么判定依据）；必须用业务/物理事实直接串联逻辑（如："基于第 3 章解出的流速分布，本章重点校验……"），严禁使用元语言套话（如"本章在全文中起到承上启下的作用……"）。单章短文无需导言。

**数据与结构原生化（导出/渲染刚性约束）**：文档需要导出为 DOCX/PDF 或渲染为 HTML 时，图表、公式、表格必须原生化表达，**禁止 ASCII 字符画与文本近似**。本工具会将以下语法无损转为 Word 原生元素：

| 内容需求 | 应该用 | 不要用 |
|---|---|---|
| 数据图表（柱/折线/饼） | ```chart 围栏 + JSON（见 reference.md） | ASCII 数据表 |
| 流程/时序/架构/状态图 | ```mermaid 围栏（flowchart/sequence/gantt/pie/class/state；中文标签直接可用） | ASCII 字符画、纯文字描述流程 |
| 数学表达 | LaTeX：`$...$` 行内、`$$...$$` 块级 | 文本近似（`x^2`、"x 的平方"、"三分之四"式自然语言） |
| 合并单元格 | 原生 `<table>` + `colspan`/`rowspan` | 拆行或省略结构（管道表格不支持合并） |
| 单元格内换行/强调 | `<br>`、`<b>` 等行内标签 | `<div>`/`<p>`（会被解包） |
| 各章另起页 | 什么都不用写——`# 一级标题`（章）自动分页，模板 Heading 1 样式自带段前分页 | 章间再放 `---`（冗余，转换器会自动去重） |
| 章内强制分页 | `---` 水平线：docx/PDF 转为分页符（长章内大节间、附录前使用；紧跟一级标题或文末时自动去重，不产生空白页；html 保留水平线） | 手工空行凑页 |
| 参考文献引用 | 正文直接写角标 `[1]`、`[2,3]`、`[1-3]`；文末加 `## 参考文献` 章节，条目按标准格式罗列（如 `[1] 作者. 题目[J]. 出处, 年份.`，`[J]` 为文献类型标识）逐条一行（或有序列表），角标与条目编号严格一一对应 | `<sup>` 包裹角标、手写 `<a>` 链接、无编号条目 |

**图表题注（可选，图与表同规则）**：是否加题注由你根据文档体裁与引用需要决定，不加同样是合法选择。决定加编号题注时遵循：

- 写法（全部为 pandoc 原生语法）：mermaid/chart 围栏参数写 `alt="图 1 系统部署流程图"`（围栏被替换为图片后，alt 即原生 implicit_figures 的图注通道）；管道表格在表格下一行写 `: 表 1 主要设备参数表`（等价形式 `Table: 表 1 主要设备参数表`，pandoc table_captions 扩展）；原生 `<table>` 用 `<caption>` 标签；普通图片独占一段写 `![图 1 系统架构](arch.png)`——alt 文本即图注，需要题注与无障碍描述分离时用 `![图 1 系统架构](arch.png){alt="系统架构示意图"}`
- 管线自动排版题注位置（图注在图下、表注在表上），但不做自动编号——编号由作者写入题注文本，全文连续、图表分开计数，并与正文引用一致（正文以"如图 1 所示"引用）。不支持 `{#fig:…}`/`{#tbl:…}` 交叉引用标识符（pandoc-crossref 生态，写入会被静默忽略），请勿使用
- 题注须自明：不看正文也能理解该图表
- 经验边界：正式报告/论文/标书中承载论证的图表通常应有编号题注；装饰配图、紧邻操作步骤的截图、周报/纪要等无编号体系文体里的小图表通常可省略。alt 留空即无图注

**参考文献自动交叉引用**：只要文档有 `## 参考文献`（或 References/Bibliography）章节且条目带 `[n]` 编号，转换时会自动把正文角标变成上标超链接，点击跳转到对应条目（Word 中即 Ctrl+点击的交叉引用）。角标编号必须与条目编号一一对应，解析不到的角标会保留纯文本并在 `warnings` 提示；个别文档不想启用时在 front matter 写 `citations: false`。不支持 pandoc 的 `[@key]` citeproc 引用语法（依赖 .bib 文件），引用一律按 `[n]` 角标 + 编号条目的通用习惯书写。

**LaTeX 写法**：优先标准 amsmath 语法（行内 `$...$`、块级 `$$...$$`，公式内可直接用中文 `\text{中文}`）。公式编号 `\tag{X}` 会自动改写为可见的 `(X)`，无需手写编号；texmath 不认识的宏会让该条公式退化为纯文本（不中断转换，`--verify` 可查出）。已实测无损的构造清单见 [reference.md](reference.md) 能力矩阵。

- **克制规则**：只在内容确实需要时使用图表与公式，不要为了版面丰富强加
- Mermaid 围栏参数：```` ```mermaid {theme=dark width=30% alt=图名} ````（width 需带单位：%/in/cm/mm；alt 缺省时无图注，文档中不会出现默认图表标题；主题缺省黑白，写 theme=dark/default 等可按图覆盖）。不写 width 时图默认撑满模板正文区宽（超高按页高收窄）；节点标签自动换行，无需手工 `<br/>`
- 耗时预期：纯文本 <1s；含图首次 5–30s、缓存命中 <2s

**front matter 配置**（题名等用 pandoc 原生顶层元数据；管线开关写在 `md2docx:` 段）：

```yaml
---
title: 文档题名                 # pandoc 原生：Title 样式渲染在封面、不入目录
subtitle: 副题名                # 可选，紧随题名竖向堆叠
toc-title: 目录                # 自动目录的标题（默认英文 Table of Contents）
md2docx:
  toc: true                   # 有章节的正式文档启用；短文档（便签/说明/周报）不需要目录，删除本行即可
  toc_depth: 3
  citations: true              # 引用角标 → 参考文献交叉引用（默认开启，按文档可关）
  reference_doc: template.docx   # 相对 md 所在目录
---
```

启用 `toc` 时**不要手写 `## 目录` 章节**——自动目录带页码、可点击、随内容刷新，手写列表与之重复，且手写标题自身会混入自动目录条目。工具已把目录域标记为打开时自动更新（OOXML updateFields 标准）：用户在 Word/WPS 中打开即见完整目录，无需任何手动步骤。

**题名与目录的位置形式（按体裁选择）**：**最普通的短文档（便签、说明、简单方案、周报）没有目录**——front matter 省略 `toc` 即可，题名用元数据或正文 H1 均无副作用（文档日后可能扩成章节体或加目录的，用元数据更稳）。有目录的正式文档，题名一律在目录之前，变化的是摘要等前置内容——企业报告/标书为"封面 → 目录 → 正文"；学位论文（GB/T 7713.1）为"封面 → 摘要 → 目录 → 正文"；科技/结题报告两种皆可，按提交单位模板定。落地规则：

- **有目录时，题名用顶层元数据、不写正文 `# H1`**：H1 会以 Heading 1 进入目录条目、且排在目录之后；改用顶层 `title:`（可选 `subtitle:`）与 `toc-title:`，题名以 Title 样式渲染在最前、不入目录，输出顺序为 题名 → 目录 → 正文
- **长题名拆为主标题 + 副标题，竖向堆叠**：`title:冷站数字孪生与模型预测控制平台（DeepAir）` + `subtitle:课题结题报告`——副标题以 SubTitle 样式紧随主标题之下居中排列，避免长题名一行排到底
- **目录文档自动三节化**：工具按正式排版惯例自动分节——**封面节**（题名/副题名垂直居中、不编页码）→ **目录节**（罗马页码 I、II）→ **正文节**（阿拉伯页码从 1 重排，目录所列即正文节内页码）；并写入 OOXML 标准的 `w:updateFields` 标记——用 **Word** 打开文档即自动生成带页码目录，零手动操作（WPS 不识别该标记，需 Ctrl+A → F9 刷新一次；交付 WPS 用户时提示这一点）
- **摘要位置随体裁**：报告类把摘要作为正文（被目录收录，属常规）；学位论文式"摘要在目录前"本管线暂不直接支持，需按模板后期调整
- **摘要位置随体裁**：报告类把摘要作为正文（被目录收录，属常规）；学位论文式"摘要在目录前"本管线暂不直接支持，需按模板后期调整
